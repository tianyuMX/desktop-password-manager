# 桌面密码管理器 V1 开发文档（Electron + Vue 3）

## 1. 文档目的

本文档用于指导 **codeX** 开发桌面密码管理器 V1。

目标是做出一个 **纯本地、离线、单用户、无后端** 的桌面密码管理器，支持：

- 首次创建主密码
- 启动后先解锁
- 按分类管理网站
- 每个网站下管理多个账号密码
- 点击网站地址跳转到默认浏览器
- 本地加密保存数据
- 支持手动锁定与自动锁定

本文档优先追求 **V1 可落地**，不追求一步到位做成大型产品。

------

## 2. 产品定位

这是一个本地桌面密码保险箱，而不是云密码服务。

### 2.1 产品定义

- 桌面端应用
- 无账号系统
- 无云同步
- 无后端
- 单设备本地使用
- 单一密码库
- 单一主密码解锁

### 2.2 目标用户

- 个人用户
- 需要在本机管理多个网站/应用账号密码的用户
- 希望通过分类整理账号信息的用户

### 2.3 V1 核心价值

用户可以在本地安全地完成以下事情：

1. 打开应用后输入主密码解锁
2. 按分类查看网站
3. 每个网站下维护多个账号密码
4. 一键复制用户名/密码
5. 点击网站地址打开对应网站
6. 锁定后再次输入主密码才能访问数据

## 4. 信息架构

V1 的核心数据层级为：

**分类 -> 网站 -> 账号**

说明：

- 一个分类下有多个网站
- 一个网站下有多个账号
- 每个账号有独立的用户名和密码

### 4.1 示例

- 分类：工作
  - 网站：GitHub
    - 账号：[work@company.com](mailto:work@company.com) / 密码A
    - 账号：[admin@company.com](mailto:admin@company.com) / 密码B
  - 网站：Jira
    - 账号：[ops@company.com](mailto:ops@company.com) / 密码C
- 分类：个人
  - 网站：Gmail
    - 账号：[abc@gmail.com](mailto:abc@gmail.com) / 密码D
    - 账号：[backup@gmail.com](mailto:backup@gmail.com) / 密码E

## 5. V1 功能范围

## 5.1 启动与解锁

### 5.1.1 首次启动初始化

当应用第一次启动，且本地不存在密码库时：

- 显示初始化页面
- 用户输入主密码
- 用户再次确认主密码
- 点击“创建密码库”
- 系统创建本地密码库文件
- 创建成功后进入主界面

### 5.1.2 后续启动解锁

当本地已存在密码库时：

- 启动后直接进入解锁页
- 用户输入主密码
- 校验成功后解锁并进入主界面
- 校验失败时提示“主密码错误”

### 5.1.3 锁定

应用支持以下锁定方式：

- 用户手动点击“锁定”
- 最小化后自动锁定（可配置）
- 无操作超时后自动锁定（可配置）

锁定后：

- 主界面不可继续访问
- 需要重新输入主密码
- 内存中敏感数据应清理或置为不可访问状态

------

## 5.2 分类管理

### 5.2.1 V1 分类策略

V1 使用 **固定分类 + 用户可修改名称（可选）** 或 **固定分类不可编辑** 均可，建议先采用固定分类，不做自定义分类管理页面。

建议内置分类：

- 工作
- 个人

### 5.2.2 分类用途

- 每个网站必须归属一个分类
- 左侧侧边栏支持按分类筛选网站
- 默认支持查看“全部”

------

## 5.3 网站管理

### 5.3.1 网站是主条目

每个网站是一个主对象，用于聚合同一网站下的多个账号。

### 5.3.2 网站字段

每个网站包含以下字段：

- `id`：唯一标识
- `name`：网站名称，必填
- `url`：网站地址，可选但建议填写
- `category`：所属分类，必填
- `tags`：标签数组，可选
- `note`：备注，可选
- `createdAt`：创建时间
- `updatedAt`：更新时间
- `accounts`：账号列表

### 5.3.3 网站操作

支持以下操作：

- 新增网站
- 编辑网站
- 删除网站
- 查看网站详情
- 打开网站
- 复制网站地址

### 5.3.4 网站地址行为

- 网站详情中若存在 `url`，显示“打开网站”按钮
- 点击后使用系统默认浏览器打开
- 不在应用内部内嵌网页
- 若 `url` 为空，则隐藏打开按钮
- 若 `url` 格式非法，则提示错误，不执行跳转

### 5.3.5 删除网站规则

删除网站时：

- 必须弹出二次确认
- 删除网站将连同其下所有账号一起删除
- 删除操作执行后应立即持久化保存

------

## 5.4 账号管理

### 5.4.1 账号属于网站

账号是网站的子项，不单独在一级列表中存在。

### 5.4.2 账号字段

每个账号包含以下字段：

- `id`：唯一标识
- `username`：用户名/邮箱/手机号，必填
- `password`：密码，必填
- `note`：备注，可选
- `isDefault`：是否默认账号，默认 false
- `createdAt`：创建时间
- `updatedAt`：更新时间

### 5.4.3 账号操作

支持以下操作：

- 新增账号
- 编辑账号
- 删除账号
- 查看账号信息
- 复制用户名
- 复制密码
- 显示/隐藏密码
- 设为默认账号

### 5.4.4 默认账号规则

- 每个网站最多只有 1 个默认账号
- 若网站下仅有 1 个账号，可自动设为默认账号
- 当用户将某账号设为默认时，同网站下其他账号的 `isDefault` 自动变为 false

### 5.4.5 删除账号规则

- 删除账号前必须二次确认
- 若删除的是默认账号，且该网站下还有其他账号，则删除后系统自动将第一个账号设为默认，或要求用户重新指定默认账号，二选一即可，建议自动指定第一个
- 若该网站下只剩最后 1 个账号，允许删除；删除后网站保留为空网站，或禁止网站无账号，二选一必须明确

#### V1 建议策略

**允许网站暂时没有账号。**

理由：

- 便于用户先录入网站信息，后续再补账号
- 简化删除逻辑

### 5.6.2 复制密码

- 在账号项中提供“复制密码”按钮

### 5.6.3 显示/隐藏密码

- 密码默认隐藏
- 用户主动点击后显示
- 再次点击后隐藏
- 列表中不直接展示完整密码

## 5.7 设置

V1 设置页包含以下内容：

- 修改主密码
- 自动锁定时间
- 最小化是否自动锁定
- 剪贴板自动清空时间
- 是否默认隐藏密码（建议默认开启）

### 5.7.1 修改主密码

流程要求：

- 输入旧主密码
- 输入新主密码
- 再次确认新主密码
- 验证通过后重新加密密码库并保存

## 9. 本地存储与安全要求

## 9.1 存储要求

- 所有业务数据存储于本地文件
- 数据文件保存于应用私有数据目录
- 落盘必须为密文，不得直接以明文 JSON 保存密码库

## 9.2 主密码要求

- 主密码不允许明文保存
- 主密码用于解锁密码库
- 修改主密码后，需要重新加密密码库

## 9.3 运行时要求

- 解锁后数据可在内存中使用
- 锁定后不得继续展示敏感数据
- 锁定后应清理或重置解锁态

## 9.4 剪贴板要求

- 支持复制密码到剪贴板
- 若开启自动清空，则达到设置时间后清空剪贴板

## 9.5 安全底线

V1 至少满足以下底线：

- 启动必须先解锁
- 密码落盘必须加密
- 删除敏感内容前有确认
- 密码默认隐藏
- 锁定后不能直接回到主界面继续查看数据

------

## 10. 状态流转

## 10.1 应用状态

V1 可抽象为以下状态：

- `uninitialized`：未初始化
- `locked`：已锁定
- `unlocked`：已解锁

## 10.2 状态流转图（文字版）

- 启动应用
  - 若无密码库 -> `uninitialized`
  - 若有密码库 -> `locked`
- 创建密码库成功 -> `unlocked`
- 解锁成功 -> `unlocked`
- 手动锁定 -> `locked`
- 自动锁定 -> `locked`
- 退出应用 -> 结束

------

## 11. 交互规则清单

### 11.1 网站相关

- 新建网站后自动选中
- 删除网站必须确认
- 若当前选中网站被删除，则右侧显示空状态
- 点击网站地址时调用系统默认浏览器

### 11.2 账号相关

- 新建账号后出现在当前网站详情列表中
- 删除账号必须确认
- 密码默认隐藏
- 复制密码后给出提示

### 11.3 搜索相关

- 搜索结果应随输入实时更新，或按回车执行，二选一即可，建议实时更新
- 搜索仅针对当前本地数据，不涉及网络请求
- 切换分类后，搜索结果基于当前分类范围

### 11.4 锁定相关

- 锁定后页面切回解锁页
- 锁定前若正在编辑，可直接关闭编辑弹窗
- 锁定后需要重新输入主密码

## 12. 错误与异常处理

V1 至少处理以下异常：

- 主密码错误
- 密码库文件不存在或损坏
- 创建密码库失败
- 保存密码库失败
- 打开网站失败
- 剪贴板写入失败

建议所有错误都提供：

- 用户可读提示
- 不导致应用崩溃

## 13. 验收标准（Acceptance Criteria）

以下条件全部满足，视为 V1 完成。

## 13.1 初始化与解锁

- 首次启动时可以成功创建主密码并进入主界面
- 二次启动时必须先输入主密码才能进入主界面
- 主密码错误时不能进入主界面

## 13.2 网站管理

- 可以新增网站
- 可以编辑网站
- 可以删除网站
- 可以给网站设置分类
- 可以填写并保存网站地址
- 点击网站地址可在默认浏览器打开

## 13.3 多账号管理

- 一个网站下可新增多个账号
- 可分别编辑和删除每个账号
- 可为某个账号设置默认账号
- 复制用户名和复制密码可正常工作

## 13.4 本地存储

- 关闭应用后再次打开，数据仍存在
- 数据文件落盘不是明文密码内容

## 13.5 锁定

- 点击锁定后，应用返回解锁页
- 开启最小化自动锁定后，最小化会触发锁定
- 开启超时自动锁定后，达到时间会触发锁定

## 13.6 设置

- 可以修改主密码
- 可以修改自动锁定时间
- 可以设置复制密码后自动清空剪贴板

## 15. 对 codeX 的明确开发要求

1. 严格按 **分类 -> 网站 -> 账号** 结构实现
2. 网站必须支持多个账号，不要把账号平铺成一级资源
3. 网站地址必须支持点击跳转默认浏览器
4. 不要在 V1 引入云同步或后端设计
5. 落盘必须是密文，不接受明文存储密码
6. 页面优先保证功能完整，不优先做复杂动画
7. 优先保证解锁、存储、锁定这三块逻辑稳定
8. 所有删除操作必须二次确认
9. 所有密码默认隐藏
10. 代码结构需便于后续扩展导入导出、密码生成器、托盘等功能

## 17. 一句话总结

V1 要做的是一个 **本地离线桌面密码管理器**：

- 先解锁
- 按分类管理网站
- 每个网站下管理多个账号密码
- 可打开网站
- 可复制账号和密码
- 可本地加密保存
- 可自动锁定

只要这套闭环完成，V1 就可以进入可用状态。
